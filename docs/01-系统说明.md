# 一、系统说明

## 1.1 项目目标

这个项目要做的是一个简化版的在线问卷系统，能完成“注册账号、创建问卷、把链接发给别人填写、查看统计”这一整条流程。功能上参考问卷星和 Google Forms，但没有做复杂的界面和高级题型，重点放在 MongoDB 的数据组织和后端逻辑上。

第一阶段的需求文档里明确了几件事：用户只能看到自己的问卷；填写的人必须先登录；题目支持单选、多选、文本填空、数字填空；跳转规则要能在问卷里配置，不能写死在代码里；每次填写都要保存；统计要根据已有回答实时算出来。

## 1.2 功能范围

账号部分做了注册、登录、退出和“当前登录用户”查询。注册时用户名限制 3 到 20 位，密码最少 6 位。密码不是明文存储，用 Node 自带的 scrypt 加盐哈希。

问卷部分可以创建、查看列表、修改基本信息、发布、关闭。创建时可以填标题、说明、是否允许匿名、截止时间。每份问卷有一个 `/survey/:id` 的填写链接。发布前可以随便改题目，发布后题目锁定，只能改标题、说明、截止时间和匿名设置。问卷关闭或者过了截止时间，链接就打不开了。

题目有四种：单选、多选、文本填空、数字填空。单选题可以设多个选项；多选题可以设最少和最多选择数量；文本题可以设最少和最多字数；数字题可以设最小值、最大值以及是否必须为整数。每道题都可以设为必答。

跳转规则按题目配置。单选题和多选题按“选中了哪些选项”判断，多选题可以选“满足任意一个”或“全部满足”；数字题按等于、不等于、大于、大于等于、小于、小于等于判断。满足条件就跳到指定题目，不满足就按顺序进入下一题。

填写页一次显示一道题，点“下一题”时先在浏览器里校验，再根据跳转规则找下一题。提交时服务端会重新按题目顺序和跳转规则走一遍，只保存真正经过的题目，客户端多传的答案会被丢掉。这样跳转逻辑以服务端为准，改前端脚本也绕不过校验。

统计页按题目展示。单选和多选显示每个选项的人数和百分比，数字题显示作答人数、平均值、最小值和最大值，文本题列出所有填写内容。统计是每次请求时用聚合管道现算的，没有另存一份统计结果。

## 1.3 技术选型

后端用 Node.js 和 Express。选它主要是因为前后端都是 JavaScript，页面里复制一份校验逻辑比较方便，不用维护两套语言。数据库访问直接用官方的 mongodb 驱动，没有用 Mongoose。原因有两个：一是课程重点是 MongoDB 设计，用原生驱动能把集合、校验器、索引写清楚；二是 Mongoose 的 schema 容易让人误以为数据库本身有约束，实际上约束还是要在 MongoDB 里建。

数据库用 MongoDB，所有业务数据都在里面，没有用 MySQL 或 SQLite 之类的工具。

前端是原生 HTML、CSS 和 JavaScript，没有构建步骤，也没有用 Vue 或 React。页面一共五个：登录注册、我的问卷、问卷编辑、填写问卷、统计结果。这样代码量小，老师下载后 `npm install` 就能跑。

登录状态用 express-session，浏览器里存一个 httpOnly 的 cookie。这一版 session 存在进程内存里，重启服务要重新登录。课程作业可以接受，文档里也把它列为已知限制。

## 1.4 系统结构

请求分为三类：

- `/api/auth/*` 处理注册、登录、退出和当前用户。
- `/api/surveys/*` 是创建者接口，全部要求登录，并且会检查问卷是不是当前用户的。
- `/api/public/surveys/*` 是填写者接口，也要求登录，但只返回已发布问卷的公开字段。

服务端分成路由、服务两层。路由负责参数和权限，`services/` 下面放题目配置校验、答案校验与跳转、统计、密码。这样跳转和校验的逻辑可以单独测，路由里不用堆一大段判断。

数据流大致是：编辑页保存题目 → 服务端校验题目配置并写入 questions 集合 → 发布后填写页读取题目 → 提交时服务端重放路径并写 responses → 统计接口按 surveyId 聚合 responses。

## 1.5 角色和权限

系统只有两种角色，没有管理员。

创建者：能看自己的问卷列表、编辑自己问卷的题目和设置、发布和关闭、看统计。访问别人的问卷详情或统计会返回 404，不暴露问卷是否存在。

填写者：必须登录。能打开已发布且未截止的问卷、提交回答。允许匿名的问卷可以选择匿名提交，这时响应文档里不保存用户 id。同一个人可以重复填写，需求里没有要求限制次数。

## 1.6 有意没做的部分

- 没有做题目排序和拖拽。题目按添加顺序编号，删除后编号会留空，不影响填写顺序。
- 没有做“上一题”。跳转可能跳过题目，回退会让路径和已答内容变得很难解释。
- 没有做问卷复制、模板、导出 Excel。
- 没有做管理员后台和封禁用户。

这些不影响本阶段的需求，第二阶段如果提出再在这个基础上加。
